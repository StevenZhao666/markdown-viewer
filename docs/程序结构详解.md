## 一、总览：一句话认识整个程序

```
OpenMarkdown.bat（双击入口）
  → OpenMarkdown.ps1（检测端口 18520、启动 helper.py）
    → 浏览器打开 http://localhost:18520/?file=路径.md
      → viewer.html（整个编辑器，纯前端）
        → 读写文件走 helper.py 的 /api/read /api/write
```

关键点：

- `viewer.html` 是**唯一的主程序**——界面、逻辑全在里面。一个文件 = 一个应用。
- `helper.py` 只是个**本地小服务器**：把 viewer.html 发给浏览器 + 提供读写文件的两个接口。
- **不能 `file://` 直接打开**（浏览器安全限制读不了本地文件），必须走 localhost。

## 五、⭐ 公式编辑器（v4.3 重构后：Atom 树模型）

这是你改「嵌套」的主战场。v4.3 把公式编辑器重构为**单一数据源模型**（参考 MathLive 思路）：

> **公式 = 一棵对象树。所有操作都围绕这棵树**：
> 渲染 = 树 → HTML DOM
> 序列化 = 树 → LaTeX 字符串
> 解析 = LaTeX 字符串 → 树
> 编辑 = 改树里的节点 → 重新渲染

### 5.1 节点类型（树里只有这 9 种）

| type | 结构 | 含义 | 生成 LaTeX |
|------|------|------|-----------|
| `text` | `{type:'text', value:'x'}` | 普通文本 | `value` 原样 |
| `placeholder` | `{type:'placeholder'}` | 占位符（虚线框） | `?` |
| `frac` | `{type:'frac', num:[], den:[]}` | 分式 | `\frac{num}{den}` |
| `sqrt` | `{type:'sqrt', body:[]}` | 根号 | `\sqrt{body}` |
| `subsup` | `{type:'subsup', base:[], sup:[], sub:[]}` | 上下标 | `base^{sup}_{sub}` |
| `int` | `{type:'int', from:[], to:[], body:[]}` | 积分 | `\int_{from}^{to}{body}` |
| `sum` | `{type:'sum', sym:'Σ'|'Π', from:[], to:[], body:[]}` | 求和/累乘 | `\sum_{from}^{to}{body}` |
| `lim` | `{type:'lim', from:[], body:[]}` | 极限 | `\lim_{from}{body}` |
| `mtx` | `{type:'mtx', cols, rows, cells:[[[...]]]}` | 矩阵(bmatrix) | `\begin{bmatrix}...` |

**树的样子**（例：分式内嵌根号 `\frac{\sqrt{x}}{2}`）：

```js
feTree = [
  { type:'frac',
    num: [ { type:'sqrt', body: [ {type:'text', value:'x'} ] } ],
    den: [ { type:'text', value:'2' } ] }
]
```

### 5.2 四个方向的转换函数

```
        feParse(latex)                feTreeToLatex(tree)
LaTeX ─────────────────→  feTree  ─────────────────→ LaTeX
                           │  ▲
        feNodeHTML(node,path)  feCommitEdit(parse后的新节点)
                           ▼  │
                          DOM `#feCanvas`  （用户看到的可视化块）
```

### 5.3 核心函数逐个讲

#### (1) `feParse(latex)` —— LaTeX → 树（1501 行）
一个**递归下降解析器**（简化版）。内部有 4 个工具函数：

- `skip()`：跳过空格
- `braced()`：读一个 `{...}` 组，返回组内字符串（**处理嵌套花括号**，用深度计数 d）
- `group(str)`：把一段字符串当成顶层，递归调用 `one()` 解析成节点数组
- `scripts(arr)`：处理 `^` `_` 后缀（上标/下标）——注意它只处理**最后一个节点**的后缀

主循环 `one(arr)`：每遇到一个字符就决定生成什么节点：
- `{` → 花括号组，展开成多个节点
- `\` → 匹配 `\frac|\sqrt|\int|\sum|\prod|\lim` → 结构节点；否则按 `\<字母>` 当 text
- `^`/`_` → 直接生成 subsup
- `?` → 占位符
- 其他可打印字符 → text；只能产生 1 个字符的也当 text

**⚠️ 这是"精简版"，读到的东西里它有限制**（见 §6.4 疑点清单）。

#### (2) `feTreeToLatex(nodes)` —— 树 → LaTeX（1601 行）
递归，switch 按 type 生成 LaTeX，每层都有 `||[]` 兜底防 undefined。placeholder 输出 `?`。

#### (3) `feNodeHTML(node, path)` —— 树 → DOM（1623 行）
递归生成 HTML 字符串。**每个节点都带**：
- `data-path="0.num.0"`（路径字符串，数字索引和字符串键混排）
- `onclick="event.stopPropagation();feEditNode('0.num.0')"`（**点任意节点 → 进入源码编辑**）

`stopPropagation` 是历史修复（2026-07-29）：否则点占位符会冒泡触发父节点（分式）的 feEditNode，重渲染把编辑框干掉。

#### (4) `feRender()` —— 整树重渲染（1646 行）
`c.innerHTML = feTree.map((n,i)=>feNodeHTML(n,[i])).join('')` 然后 `_feSyncLatex()`。**全量重建**，不是差异化更新。⚠️ 函数里有一段空的 `if(editingPath){...}` 幽灵代码（1649-1653 行），没逻辑，注释写着"简单处理"。

#### (5) `feEditNode(pathStr)` —— 点击节点 → 局部源码编辑（1660 行）
流程：
1. `_feSub(feTree, path)` 在树里找到这个节点
2. `_feEditingPath = path`，重渲染（让该节点有 `fe-editing` 样式高亮）
3. 用 `querySelector('.fe-node[data-path="..."]')` 找到它的 DOM，`replaceWith()` 换成 `contenteditable` 源码框 `fe-edit-box`
4. 框内显示该节点的 LaTeX（`feTreeToLatex([node])`，可含嵌套结构）
5. **Enter 提交 / Esc 取消 / 失焦提交**

#### (6) `feCommitEdit(inp, path)` —— 提交编辑（1691 行）
- 读源码框文本 → `feParse(src)` 解析成**新节点数组**
- `_feParentPath(feTree, path)` 找父数组和索引
- 按结果替换：0 个 → `splice(idx,1)` 删除；1 个 → 覆盖；多个 → 展开替换
- `feRender()` 重渲染
- 有 `_feCommitting` 标志防 blur 二次触发（幂等保护）

#### (7) `_feSub(nodes, path)` / `_feParentPath(nodes, path)`（1618-1619 行）
按路径数组在树里定位：`_feSub` 一直往下走；`_feParentPath` 返回 `{parent, idx, ppath}`。

#### (8) 模板按钮（1712-1719 行）
```js
function _fePush(node){ feTree.push(node); _feEditingPath=null; feRender(); }
function feAddFrac(){ _fePush({type:'frac',num:[{type:'placeholder'}],den:[{type:'placeholder'}]}); }
function feAddSqrt(){ ... }  // 根号
function feAddInt(){ ... }   // 积分
function feAddSup(){ ... }   // 上下标
function feAddSum(){ ... }   // 求和
function feAddProd(){ ... }  // 累乘（用 sum 节点 sym:'Π'）
function feAddLim(){ ... }   // 极限
function feAddMtx(){ ... }   // 矩阵（弹出 6×5 选择器）
```

**★ 注意：所有模板按钮都只 `feTree.push` 到根序列末尾**——它们不会插入到"当前选中/聚焦的槽位"里。这是嵌套体验问题的核心（见 §6）。

#### (9) 画布 ↔ 文档的交互

- `_feSyncLatex()`（1774）：`feTreeToLatex(feTree)` → 显示到 `#feLatexCode`、设置 `_canvasLatex`、控制 `#feEditor` 显隐、调 `_livePreview()` 刷新编辑框旁边的实时预览
- `feClear()`（1782）：清空树 + 所有状态 + canvas 显示提示
- `feLoadLatex(latex)`（1796）：从预览区**点已渲染公式**载入画布：`feTree = feParse(latex)`；解析不出结构就回退显示 `fe-raw` 原文框（`feUpdateRaw`）；并尝试在编辑框文本里找该公式原文，记录 `_replaceRange`（点击替换场景）
- `feInsert()`（1819）：把 `$...$`（防粘连加空格）插入编辑框光标处；若 `_replaceRange` 存在则**替换原文公式**；然后 `feClear()`

#### (10) `_livePreview()`（817 行）
编辑框输入时实时预览。**合并逻辑**：如果 `_canvasLatex` 非空：
- 有 `_replaceRange` → 用它替换原文中的公式
- 没有 → 插入到光标位置
然后 `renderMD()` → 塞进预览容器（优先 `.block-edit-preview`，回退 `#tbPreview`）→ `_renderMath()`。预览里的公式可点击（`pv.onclick` → 载入画布编辑）。

## 六、「嵌套」功能现状 & 分析（你要改的东西）

### 6.1 嵌套怎么实现（v4.8.0 起：选中槽位 → 点模板）

**主路径（点选式，v4.8.0 新增）**：

```
点模板「分式」→ 画布出现 ▢/▢
→ 单击分子的 ▢（虚线高亮 = 已选中）
→ 点模板「根号」→ 根号替换该占位槽 → 渲染成 √▢，且 √ 里的槽自动选中
→ 继续点模板可继续嵌（√ 里再嵌分式…）
→ 键盘直接打字（选中的槽变文本，如 ab）；Backspace/Delete 删除选中节点
```

**补充路径（源码式，v4.3 起一直在）**：双击任意节点 → 弹出源码小框 → 打任意 LaTeX → Enter 提交。

实现要点：单击 = 选中（`_feFocusedPath` + `.fe-focused` 虚线高亮），双击 = 源码编辑（feEditNode/feCommitEdit）。
`_fePush` 有选中节点时插进它那里（占位槽替换、其他节点插到其后），没有则追加到画布末尾；插入后自动选中新公式的第一个空槽（`_feFirstPlaceholderPath`），支持连点嵌套。

### 6.2 历史（为什么之前"支持"嵌套）

- **v4.2.0 之前**：槽位是 `contenteditable` 双面结构（编辑层+预览层，CSS 都还在 211-219 行），点槽位直接打字，能嵌套是因为有 `genBlockLatex` 递归和焦点槽位概念。skill 里记的"分式内可嵌根号"就是那个时代的产物。
- **v4.2.0** 官方声称解决已知问题 #4（嵌套）。
- **v4.3.0 重构**（commit `64d61b3`）改成 Atom 树模型——**内容编辑从"contenteditable 槽位"变成了"点击节点弹源码框"**。嵌套的"可视化"能力实际上变成了"局部 LaTeX 源码编辑"。

**注意**：项目铁律明确说"可视化优先：公式编辑绝不回退到 fe-raw 原文"。但现在每个节点编辑都是源码框——这算不算违反铁律，是你要做的判断（或者说，这正是嵌套体验"还有问题"的根源之一）。

### 6.3 树上嵌套的机制层面（技术上是通的）

从数据结构看，树的递归设计**支持任意深度嵌套**：
- `feNodeHTML` 递归渲染（子节点 path 用 `path.concat('num',i)` 构造）
- `feTreeToLatex` 递归序列化
- `feParse` 的 `group()/braced()/one()` 递归解析（嵌套花括号 OK）

所以如果只是"树模型"，嵌套没问题。问题出在**编辑交互层**。

### 6.4 疑点清单（按嫌疑排序，供你排查）

**① ✅ v4.8.0 已修：模板按钮会插进选中节点**（下面的描述是修复前的行为，留作背景）
`feAddFrac()` 等一律 `feTree.push()` 到根。用户点选一个槽位（比如分式的分子）后点「根号」模板 → 根号出现在画布末尾，不在分子里。要支持"选中槽位 + 点模板 → 嵌套"，需要：
- 记住"最后点击的节点"（类似旧版 `_focusedSlot`）
- `_fePush` 改为按目标插入：有选中节点 → `parent.splice(idx,0,node)`（或替换 placeholder），没有 → push 到根

**② ✅ v4.8.0 已修：feEditNode 的 blur 竞争 → 编辑框闪退**（做法：feRender 重建 DOM 前 `_feDropEditBox()` 摘掉旧编辑框 onblur——否则移除节点时同步 blur → feCommitEdit 重入 → innerHTML 二次赋值抛 NotFoundError；画布 mousedown 捕获时对「编辑框外」的点按 `preventDefault`，改由 feFocusNode/feEditNode 显式提交，点击不再丢）
点节点 A 弹出编辑框，此时点节点 B：A 的 `onblur` 触发 `feCommitEdit` → `feRender()` **全量重建 DOM** → 你正要点的 B 的 DOM 在 mousedown 和 click 之间被销毁 → B 的 click 不触发（或触发到别的元素）。表现：**编辑框闪退、点了没反应**。历史 commit `dd2fa7c`（点击节点冒泡触发父节点编辑-编辑框闪退）修过类似问题，但 blur+重建的竞态可能还在。修复思路：mousedown 时 cancel 编辑，或在 commit 前捕获目标并手动 dispatch。

**③ ✅ v4.8.0 已删：feRender 里的幽灵代码（原 1649-1653）**
```js
if(editingPath){
    const rootPath=editingPath.split('.').slice(0,-1).join('.');
    // 简单处理: 整树渲染, 编辑节点单独处理
}
```
空逻辑 + 注释"简单处理" = 重构中途被弃用的方案。编辑中节点实际由 feEditNode 手动替换 DOM。后果：任何在编辑过程中触发 `feRender()` 的路径（如 `_feSyncLatex` 被别处调用）都会**丢失编辑框**且 `_feEditingPath` 残留（残留后别的节点可能被误加高亮 class）。

**④ 解析器的"精简版"限制（feParse，1501-1598）**
- 上标后缀只处理"最后一个节点"（`scripts(arr)` 取 `arr[arr.length-1]`）——`x^2 y` 这类后面还有内容的场景不变形，但 `{a}{b}^2` 之类的组合可能出意外
- 不支持 `\left( \right)`、`\text{}`、`\begin{}` 等复杂命令（除了 mtx 特判）——**解析失败会静默降级**（当作一个 text 节点，value 是 `\left`，剩下的 `(` 再成 text），导致往返不一致：载入 `\left(x\right)` → 树 → 再生成 LaTeX 时结构已经变形
- `?` 被当成占位符记号：用户公式里真有 `?` 的话，载入 → 解析 → 回车会变成 placeholder 语义（设计如此，但要留意）
- 单个 `\` 命令（如 `\alpha`）→ text 节点，OK

**⑤ `_replaceRange` 的匹配（1812-1815）**
`feLoadLatex` 用正则 `\$...\$` 在编辑框文本里**找第一个**匹配。文档里有多个相同公式时替换范围可能错。另外 regex 转义 `escaped=latex.replace(/[.*+?^${}()|[\]\\]/g,'\\$&')` 把 `+` `?` 等转义了但 `{}` 也转义了，还行。

**⑥ 死代码/残留（不影响功能，但干扰阅读）**
- `_focusedSlot`（1479）：只剩声明和 feClear 里的清空，无实际用途
- `fe-slot`/`fe-slw`/`fe-slr` 双面槽位 CSS（211-219）：v4.3 后 JS 不再生成
- `.fe-sup`（230-232）与 `.fe-subsup`（185-188）重复定义；`.fe-int` 定义了两次（189-194 与 226-229），后者 grid 版生效
- `_stopTb()`（1075）：已无调用点（grep 验证）

**⑦ mtx 的路径系统（1753-1762）**
`feMtxHTML` 给单元格内节点的路径是 `path.concat('cells',ri,ci,i)`，而 `_feSub` 走 `node.cells[ri][ci][i]`——`cells[ri][ci]` 是节点数组，多一层索引。与 `feMtxLatex` 用 `feTreeToLatex(cell||[])`（cell 是数组）语义一致，但**矩阵里嵌套**时 path 长度比其他节点多 1 层，手写 path 解析时要小心。

## 七、其他模块速览（改嵌套之外的任何地方都要先看这）

### 7.1 Markdown 渲染 `renderMD()`（519 行）
一条用正则堆出来的流水线（不是标准 markdown-it！），**顺序敏感**：

```
① 提取 ```代码块 → 占位符 \x00CB0\x00（防内部 # 注释被当标题）☆未提交改动
② 表格行 → <table>（必须连续 | 行）
③ 提取 $$...$$ → 占位符 \x00MB0\x00（防被 <p> 包裹拆开）
④ `code` → <code>
⑤ 标题 # h1-h4（生成 slug 锚点 id）
⑥ 加粗/斜体/图片/链接/hr/引用/列表
⑦ 剩余行 → <p> 包裹
⑧ 还原 $$ → <div class="math-block">
⑨ 还原代码块 → <pre><code>（先剥 <p>\x00CB0\x00</p>）
```
失败模式：正则表驱动，绝大多数 markdown 都能过，但组合场景（表格里嵌代码等）会出问题。

### 7.2 块编辑系统（581-851）
- `_parseBlocks`：按空行/标题/`---` 切块。空文件塞 `['']` 占位（v4.5.0）
- `_renderBlocks`：每个 .md 块渲染成 `.block` div，**双击**进编辑
- `_editBlock`：块变 textarea + 3 个按钮（✔完成 / 📐工具栏 / 👁预览）+ 分屏 preview
- `_finishEdit`：text 内容回写 div.dataset.raw → `_updateFullText()`（合并全块 → tabs[activeTab].mdText，标 dirty）→ `_renderMath(preview)`
- `_bindScrollSync`：编辑框↔预览按比例双向同步（lock 防循环）
- `_livePreview`：输入时实时渲染（见 §5.3.10）

### 7.3 多标签页（852-1005）
`tabs` 数组是**文档状态的唯一来源**（v4.5 重构时删了 `currentMDText` 等单文件全局）。新建/打开/关闭/切换都操作数组再 `renderTabBar()`。重命名走 `_doRename`：`fileHandle.move`（Chrome 86+）→ `/api/rename`（helper.py os.rename）→ 仅改标签。

### 7.4 保存（1194-1263）
- 老文件（有 filePath）→ `/api/write` POST
- File System Access 句柄 → `createWritable()`
- 新文件 → `saveAsNewFile()`：`showSaveFilePicker` 优先，取消/不支持 → **兜底下载**（`.md` 下载到浏览器下载目录）

### 7.5 工作区未提交改动（renderMD 代码块保护）
`git diff` 显示：把代码块提取从"直接 `<pre>` 输出"改成"占位符提取 → 最后还原"，修复代码块内 `#` 注释被标题正则误伤的问题。**与嵌套无关**，但提交前注意别和其他改动混在一起。

## 九、术语表（第一次读代码往这边看）

| 术语 | 意思 |
|------|------|
| 块（block） | 预览区里按空行切分的一个段落单元，可整体双击编辑 |
| 画布（feCanvas） | 公式编辑器的工作区，显示可视化公式块 |
| 节点（node） | 树里一个单元：text/placeholder/frac/sqrt/subsup/int/sum/lim/mtx |
| 路径（path） | 从树根到一个节点的一串键，如 `[0,'num',0]`，DOM 里用 `0.num.0` |
| 占位符 | `?` / 虚线框，表示"还没填的内容" |
| KaTeX | 网页上渲染 LaTeX 公式的库（本地化在 lib/katex） |
| File System Access API | Chrome 的"真·本地文件"读写能力（文件夹手柄 dirHandle） |
